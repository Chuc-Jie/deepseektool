## 一、总体架构（数据流）

```
导航面板（scrollNav）                          对话区（虚拟列表）
┌──────────────────────────┐                ┌──────────────────────────┐
│ items: [{id,title,branchAt,branches}]       │ ds-virtual-list（虚拟列表）
│  —— 由「用户消息」生成，按 id 标识           │  —— 消息也是虚拟列表，动态加载
│                          │                │                          │
│ 点击项: setActiveId(id)  │                │ 收到 scrollNavActivateMessage
│        + 广播事件        │ ──事件总线──▶   │  scrollTo({key: id})      │
│        scrollNavActivate │   uV.j.next()  │  （虚拟列表按 key 精确定位）│
│        Message({id})     │                │                          │
│                          │                │ 滚动时: Cy 组件计算锚点    │
│ 高亮: activeId === id    │ ◀──onActive──  │  → 找锚点线所在消息 id     │
│  （纯 id 精确匹配）       │   (id)         │  → onActive(id)           │
└──────────────────────────┘                └──────────────────────────┘
```

**两条完全独立的链路**：
- **点击 → 高亮**：导航项 `onClick` 里直接 `setActiveId(id)`（即时高亮），同时广播事件让对话区滚动
- **滚动 → 高亮**：对话区滚动 → Cy 组件算锚点 → 找消息 → `onActive(id)` 更新导航高亮
- 中间通过**事件总线**（`uV.j.next/subscribe`）解耦，导航和对话区互不直接引用

## 二、源码级机制（关键片段）

### 2.1 导航组件：显示条件与宽度（bundle 源码）

```js
return r.length < 2 || (c && u) ? null : (        // ★ r = 用户消息数组
  <div className={Cj.scrollNav} onMouseEnter={()=>i(!0)} onMouseLeave={()=>i(!1)}>
    ...
    <div className={scrollWrapper, r.length > 8 ? useMaxWidth : undefined, ...}>
      <sf items={r} itemMinSize={30} itemEstimatedSize={30}
          paddingTop={15} paddingBottom={15} getKey={e=>String(e.id)} onScroll={b} />
    </div>
  </div>
)
```

- **`r.length < 2 ? null`**：用户消息 **少于 2 条 → 导航根本不渲染**
- **`r.length > 8 ? useMaxWidth`**：**≤8 条时不用 240px 固定宽度**（宽度 fit-content 自适应）
- 展开态由 `onMouseEnter/Leave` 驱动 JS 状态（`_7ae8ea4` = show 类）

### 2.2 导航项：onClick 源码（完整）

```js
onClick: () => {
  r(o),                            // setActiveId(id) —— 立即高亮（id 精确匹配）
  s.current = Date.now(),          // clickRef 打点：标记"刚由点击触发"
  uV.j.next({ method: "scrollNavActivateMessage", args: { id: o } }),  // 广播给对话区
  d.onClick()
}
```

**高亮判定**：`activeId === item.id`（纯 id 比较），点击项必高亮，与滚动无关。

### 2.3 点击跳转：对话区接收事件 → 虚拟列表按 key 滚动

```js
useEffect(() => {
  const sub = uV.j.subscribe({ next: (e) => {
    if (e.method === "scrollNavActivateMessage") {
      s.current.scrollTo({ key: String(e.args.id), debounce: false });  // ★ 虚拟列表按 key 滚动
      d.next(e.args.id);          // 同时广播 activeId
    }
    ...
  }});
  return () => sub.unsubscribe();
}, [s, d, l]);
```

**手动计算场景**（另一处滚动函数，用于非导航场景）：

```js
// 非思考消息：虚拟列表 API 取精确 offsetTop，再减 12px
let t = s.current.getOffsetTopOfKey(String(e));
s.current.scrollTo({ top: t - 12, behavior: "instant" });
// 思考消息：定位到 .ds-assistant-message-main-content，减 48px
let u = contentRect.top - listRect.top + listScrollTop - 48;
s.current.scrollTo({ top: u, behavior: "instant" });
```

- **滚动是 `behavior: "instant"`（瞬间跳转）**，不是 smooth
- 偏移量：**-12px**（普通消息）/ **-48px**（思考消息）

### 2.4 滚动联动：Cy 组件 + C_ 锚点函数（完整）

```js
Cy = memo(({ onActive, sessionId, shareId, clickRef }) => {
  const d = useCallback(() => {
    const el = getScrollEl();          // 对话区滚动容器
    if (!el || clickRef.current) return;   // ★ 刚点击过（clickRef 有值）→ 跳过联动！
    const anchor = C_(el, inputBoxH);       // ★ 计算锚点线位置
    const msgId = findMessageAtAnchor(getMessageEls(), anchor);  // 找锚点线所在消息
    if (msgId !== null) onActive(msgId);    // 更新导航高亮
  });
  // 50ms debounce + 100ms maxWait（滚动停止后才判定）
  const throttled = useMemo(debounce(d, 50, { maxWait: 100, trailing: true, leading: true }));
  bindScrollListener(throttled);       // 绑定到滚动容器的 onScroll
});

// ★ 锚点线计算 C_：
C_ = (el, t) => {
  let { scrollTop: n, clientHeight: r, scrollHeight: s } = el;
  let a = s - r;                 // 最大可滚
  let o = r - t;                 // 视口高 - 输入框高
  let l = el.getBoundingClientRect().top;
  return a < o
    ? l + n / a * o              // ★ 少量消息（内容不够滚满）→ 比例映射锚点线
    : n >= o
      ? l + r - t                // 正常滚动 → 锚点线 = 视口底部向上输入框高（固定位置）
      : l + n / o * o;           // 刚滚 → 锚点线从顶部出发
};
```

**锚点线解读**：
- 正常滚动时锚点线 = **滚动容器底部上方「输入框高度」处**（约视口底部偏上 120px），固定不动
- **少量消息（maxScroll < clientHeight - 输入框高）时锚点线改为比例映射**，从容器顶（scrollTop=0）到容器底-输入框高（scrollTop=max）平滑移动——**专门为少量消息设计的适配分支**

## 三、为什么官网没 demo 的那些问题（逐条对照）

| # | demo 的问题 | 官网的机制（为什么没问题） |
|---|---|---|
| 1 | **点击最后一项 → 高亮偏移** | 虚拟列表 `scrollTo({key: id})` **按消息 id 精确定位**，无 offsetTop 计算误差、无"越界 clamp"问题 |
| 2 | **点击后高亮被滚动联动覆盖**（"第二次才成功"） | ① 点击时 `clickRef = Date.now()` 打点，滚动联动回调里 `if (clickRef.current) return` **直接跳过**；② 滚动是 instant（无 smooth 过渡期干扰）|
| 3 | **少量消息点击偏移** | ① `<2` 条用户消息**导航不渲染**；② ≤8 条**宽度自适应**（fit-content）；③ 锚点计算有**少量消息比例映射分支**（`a < o` 时）|
| 4 | **当前项锚点线位置导致选错** | 锚点线 = 视口底部上方输入框高（120px），且按 id 精确匹配消息，配合 50ms debounce 稳定判定 |
| 5 | **消息高度不均导致映射偏差** | 官网 chat 本身是**虚拟列表**（ds-virtual-list--printable），消息位置由虚拟列表统一管理（scrollHeight 动态变化），导航点击/联动都走虚拟列表 API，不存在 demo 那种"DOM offsetTop 与滚动位置脱节" |

**一句话总结**：官网的导航与对话区**共享同一套虚拟列表数据模型（消息 id）**，
点击=按 key 精确滚动、高亮=id 精确匹配、联动=锚点线+点击标记跳过，**任何环节都不依赖
"偏移量猜测"或"滚动位置与 DOM 位置的一致性假设"**——demo 的问题全部源于这两类脆弱假设。

## 四、demo 可借鉴的改进（按优先级）

1. **✅ 已实现**：点击后锁定高亮（对应官网 clickRef 机制，demo 用 `lockedIdx`）
2. **可借鉴**：滚动改为 `behavior: "instant"`（官网同款，消除 smooth 过渡期干扰）；
   或保留 smooth 但点击后锁定更彻底
3. **可借鉴**：少量消息（≤8 条）面板**宽度自适应**（去掉 240px 固定宽，用 fit-content）
4. **可借鉴**：用户消息 `<2` 条时**不显示导航**
5. **可借鉴**：当前项锚点线参考官网位置（视口底部上方约 120px）+ 少量消息比例映射分支
6. **远期**：demo 若要把 chat 也改成虚拟列表（对齐官网架构），可解决所有"位置计算"类问题；
   但 demo 当前 DOM 流方案配合锁定机制已能保证正确性
